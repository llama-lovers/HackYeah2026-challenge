## Phase Goal

**As a** blind user, **I want to** check an InPost parcel's status by voice from start to finish, **so that** the agent never takes an irreversible, secret-entering or ambiguous step without asking me first.

(Mechanical restatement of the ROADMAP Phase 2 goal line; no story was invented.)

This plan's slice: the agent asks before it does anything irreversible. Phase 1's fail-closed refusal (D-24) becomes a spoken confirmation: "Chcę kliknąć „Zapłać”. Potwierdzasz? Powiedz tak albo nie." A locally matched "tak" executes exactly the stored proposal with no further model request; cookie-consent banners such as Didomi on inpost.pl count as legal consent.

## Assumptions adopted (no CONTEXT.md; orchestrator-recommended resolutions of RESEARCH open questions)

- Q1: the "tak" turn still uploads audio to /api/transcribe (Whisper). Roadmap criterion 3 "no extra model request" means no /api/action and no /api/effect after "tak"; the e2e proves exactly that.
- Q3: every control inside the consent container requires "tak", including "ODRZUĆ WSZYSTKO", "DOSTOSUJ", the policy link and a "Zamknij" button.
- D-24 is replaced as RESEARCH and SKELETON.md state: the unconfirmed path still never acts; it now asks instead of refusing. D-04/D-23 stay: the confirmation names the control by its DOM name (placeholder first), never by model text.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model proposal -> service worker | needs_confirmation and the target come from an untrusted model (prompt injection via page text) |
| page DOM -> content script | Labels, containers and dialog wording that drive the irreversible/consent classification are page-controlled |
| user speech -> service worker | "tak"/"nie" arrive as transcripts, possibly containing the agent's own prompt picked up by the microphone |
| service worker -> content script | The confirmed flag and the stored proposal cross into the page's isolated world |
| service worker -> chrome.storage.session | The stored proposal and masked pre-snapshot wait there between turns |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-07 | Tampering | page text prompt-injecting the model into a payment or consent click | high | mitigate | Classification is computed in the content script from the live DOM (validateProposal + consent signal); needs_confirmation false from the model changes nothing; prompt names the control from the DOM; confirm.mjs runs with a fake that always answers false |
| T-02-08 | Spoofing / Elevation | a forged confirmed flag | high | mitigate | confirmed exists only on SW -> content runtime messages (sender.id checked in content/index.ts); the SW sets it on exactly one path, after routeReply returned confirm for a claimed confirm_action; page scripts cannot send extension runtime messages |
| T-02-09 | Tampering | stale or cross-document "tak" | high | mitigate | Pending bound to tabId, claimed once inside runSerial, 60 s TTL, EXECUTE carries the stored docId and epoch and the executor still checks identity drift; confirm.mjs (c) and (d) and pipeline.test.ts prove it |
