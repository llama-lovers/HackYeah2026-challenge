## Phase Goal

**As a** blind or low-vision user, **I want to** hear progress and recover from every failed voice turn, **so that** a slow or broken page never leaves me in silence or misleads me with stale output.

<objective>
Complete Phase 3 with one turn-wide wait deadline, exhaustive safe Polish recovery, adversarial browser regression and explicit end-of-phase human checks.

Purpose: Make lifecycle races and failures observable without weakening privacy, action safety or screen-reader semantics.
Output: Durable deadline ownership, classified error messages, integrated E2E harness coverage and pending human acceptance procedure.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| asynchronous events → owned turn | Timers, STT, model, navigation and tab events can arrive after ownership changes. |
| proxy/provider errors → user speech | Untrusted diagnostics must become fixed safe categories, never verbatim output. |
| persistent preference → worker restart | Durable enum survives; page-derived conversation state does not. |

## STRIDE Threat Register (OWASP ASVS 5.0, Level 1; high severity blocks)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-12 | Spoofing / Tampering | wait timer and late results | high | mitigate | Bind to immutable turn/tab/document, persist absolute deadline/claim, serialize terminal ownership and drop stale callbacks. |
| T-03-13 | Denial of service | duplicate events/output | medium | mitigate | Once-only wait and terminal claims, bounded messages and cleanup on every exit. |
| T-03-14 | Information disclosure | spoken/logged errors | high | mitigate | Map typed codes to fixed Polish text; never interpolate raw provider, exception, utterance or page content; retain body-free logs. |
| T-03-15 | Tampering / Elevation | malformed STT/model success | high | mitigate | Runtime-decode nonempty bounded shapes before use and prove zero EXECUTE/page mutation on invalid output. |
| T-03-16 | Repudiation | post-action effect failure | medium | mitigate | State uncertainty honestly and suggest page description; do not claim success or recommend blind replay of consequential actions. |
| T-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | Add no package; restore only existing lockfiles. Any executor-proposed new package requires the legitimacy gate before installation. |
