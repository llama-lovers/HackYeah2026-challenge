## Phase Goal

**As a** blind or low-vision user, **I want to** decide how the agent speaks and silence it immediately, **so that** stale speech or actions never continue after I stop them and the screen reader never competes with browser voice.

<objective>
Deliver SAFE-05 barge-in and the single OUT-02 output policy across worker, offscreen and content contexts.

Purpose: Make stop urgent, durable across MV3 ownership boundaries and honest about batch spoken-stop latency while preventing dual speech.
Output: Dedicated stop command, discard protocol, action/output fences, explicit output-mode router and browser cancellation scenario.
</objective>

## Flagged assumptions from the spec-less edge probe

- SAFE-05 / concurrency / unresolved: the guaranteed boundary is immediate keyboard dispatch plus owner invalidation; client abort does not prove an already-started provider computation or billing stopped, and an already committed synchronous DOM effect cannot be rolled back.
- OUT-02 / unclassified / unresolved: no reliable screen-reader detection API exists, so route selection is explicit and defaults to screen-reader mode; target-machine Polish voice availability remains a human acceptance item.

## Scope and sizing justification

This 52,000-token plan intentionally owns 13 paths because the safety stop and exclusive output policy must cross the browser command entry, worker owner, offscreen recorder, content commit boundary and a trusted extension recovery surface as one demonstrably cancellable slice. Its three tasks progress from a runnable stop tracer to page fences and then complete output routing/recovery. Splitting by context would leave unsafe intermediate states where one scheduler can still speak or act after another has cancelled. Task 3's larger bounded file set is required to prove both ordinary page delivery and restricted-page recovery, while the calibrated plan estimate remains below 100,000 tokens.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Chrome command/runtime event -> service worker | Browser events and runtime messages select the cancellation owner and output route. |
| Service worker -> offscreen/content contexts | Typed messages cross independently scheduled extension contexts and may arrive late. |
| Page content -> worker execution acknowledgement | Untrusted page lifecycle may race cancellation immediately before a side effect. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | pipeline/content execution commit | high | mitigate | Persist owner invalidation, send a local cancellation generation and recheck it immediately before every DOM effect. |
| T-04-02 | Denial of service | TTS/live-region queues | medium | mitigate | Bound queues, settle cancelled promises and make stop bypass long serialized work. |
| T-04-03 | Information disclosure | dual output routes | medium | mitigate | Select exactly one route per line; explicit preference only; no screen-reader inference. |
| T-04-04 | Spoofing | runtime cancellation/output messages | medium | mitigate | Require extension sender, top-frame/document ownership where applicable and strict message decoders. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No install task exists; retain existing pinned packages and apply the package-legitimacy gate before any unplanned install. |
</threat_model>
