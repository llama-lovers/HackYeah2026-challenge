## Phase Goal

**As a** blind or low-vision user, **I want to** hear short recognizable audio cues and have recording finish after I stop speaking, **so that** routine lifecycle states are quick, private and do not require extra speech.

<objective>

Purpose: Complete VOICE-04, VOICE-05 and OUT-06 with actual lifecycle events, bounded Web Audio resources and an accessible off switch.
Output: Pure silence policy, earcon synthesizer, capture integration, settings toggle and audio browser scenario.
</objective>

## Scope and sizing justification

This 47,000-token plan intentionally owns 13 paths because one user-observable audio lifecycle crosses the shared protocol/settings contract, the worker, the sole offscreen capture/audio owner, the options control and the existing CDP harness. The three tasks stay vertically runnable: Task 1 proves silence plus the two microphone boundary cues without depending on later work; Task 2 expands that player to all five owned cues; Task 3 adds preference/fallback behavior and makes the shared harness cue-aware. Splitting these paths into independent plans would duplicate ownership of `offscreen.ts`, `pipeline.ts` and the audio scenario while leaving intermediate tasks unverifiable. Each task has a bounded behavior set and the calibrated estimate remains below 100,000 tokens.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Microphone stream -> offscreen analyser/recorder | Private live audio enters two resource-owning Web Audio/recording paths. |
| Worker lifecycle -> offscreen cue player | Typed events may arrive late, duplicate or after document recreation. |
| Options storage -> worker/offscreen behavior | Unknown or failed preference writes must not cause silence or stale state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05 | Information disclosure | microphone analysis graph | high | mitigate | Never connect analyser/microphone source to audible destination; release tracks/context on every exit. |
| T-04-06 | Denial of service | detector timers and oscillator queue | medium | mitigate | One capture/cue owner, bounded timers/sources, idempotent release and the existing 25-second cap. |
| T-04-07 | Tampering | late/duplicate cue events | medium | mitigate | Bind every play/cancel message to owner generation and map cues only from measured lifecycle transitions. |
| T-04-08 | Repudiation | inaccessible audio-only state | low | mitigate | Keep programmatic checkbox/status state and selected-route textual fallback when cues are disabled. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No install task exists; native Web Audio is used and any unplanned package requires the package-legitimacy gate. |
</threat_model>
