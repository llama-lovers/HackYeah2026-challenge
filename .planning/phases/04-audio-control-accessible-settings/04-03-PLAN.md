## Scope and sizing justification

This 60,000-token plan intentionally owns 12 paths because exact preview is one cross-language acceptance contract: the options controls, trusted worker message path, local TypeScript reconstruction, versioned provider-envelope data, Python runtime configuration and captured backend-body parity must change together. Its three tasks remain bounded and user-verifiable: accessible persistent settings, executable provider-envelope parity, then the side-effect-free current-page preview and end-of-phase human check. A separate schema/backend plan would leave the UI able to claim exactness before parity exists. The calibrated estimate remains below 100,000 tokens, and no task adds a model route, provider call or AI system.
